# Featurize RTX 4090 按量实例操作手册

> 平台：**飞致云 / Featurize**，按量 4090（约 25.2GB 显存）。  
> 没有「关机」，只有 **退还实例** = 系统盘清空。  
> 能留下来的只有：`/home/featurize/work`（云盘，慢）和你点的 **「创建镜像」**。  
> 生产跑离线包，**不要**在实例上 clone 源码、不要 `rebuild-llama`、不要编译 CUDA。  
> 源码仓 `Dockerfile.llama` 钉 **b5512** 是构建目标，**尚未用该 Dockerfile 在 4090 重编冒烟**，不要对外写「源码钉版 `--mmproj` 已修好」。  
> 2026-09-07/08 核实的是仓库外离线包 + 自定义镜像：六容器 healthy（含 vision），`gpu-quick` 通过，`gpu-full` 因 L2 缓存未过。`gpu-quick` 不能写成「GPU 全量通过」。

本文是「每次怎么做」。改镜像/修 bug 见 [GPU 容器化修复步骤](./2026-09-07_GPU容器化修复步骤.md)。

SSH **端口每次新租都会变**。从实例页复制，例如：

```text
ssh featurize@workspace.featurize.cn -p <本次端口>
```

栈起来之后，**不要手点页面验收**。公司电脑怎么测（生死 vs 全量）：[飞致云五层两档测试说明](../2026-09-07_飞致云五层两档测试说明.md)。上机清单见 [GPU全量校验手册 §12](../GPU全量校验手册.md#12-飞致云公司电脑一键编排)。若公司电脑本机 Docker 已占 8088/5000/8080/8081，脚本会改绑 18088/15000/…，否则 Gate1 测的是本机栈（没有 8083）。`gpu-quick` 不能写成「GPU 全量通过」。

## 0. 每次退还前必做（先拷数据，再点退还）

**忘了这一步，库、日志、登录密钥全没。** 先跑完本节，确认 `~/work/agent1-backup/<日期>/` 里有文件，再点「退还实例」。

在 **gpu 目录**（有 `docker-compose.yml` 的那个）执行：

```bash
# 改成你的 gpu 目录；本轮解压路径是：
GPU_DIR=/opt/agent1/容器化部署/gpu
# 瘦拷完成后也可能是：GPU_DIR=/opt/agent1/gpu
# 找不到就：GPU_DIR=$(find /opt/agent1 -name docker-compose.yml | head -1 | xargs dirname)
cd "$GPU_DIR"

STAMP=$(date +%Y%m%d-%H%M)
DEST=/home/featurize/work/agent1-backup/$STAMP
mkdir -p "$DEST"
echo "备份目录: $DEST"

# 1) 数据库（最重要）
sudo docker compose exec -T postgres pg_dump -U postgres chemical_park_ai_agent \
  | gzip > "$DEST/db.sql.gz"

# 2) API 日志卷（Serilog / 审计 jsonl 等）
sudo docker run --rm \
  -v agent1_api_logs:/src:ro \
  -v "$DEST":/dst \
  alpine:3.20 tar czf /dst/api-logs.tgz -C /src .

# 3) DataProtection 密钥（不拷回来下次登录 cookie 会失效）
sudo docker run --rm \
  -v agent1_api_dataprotection:/src:ro \
  -v "$DEST":/dst \
  alpine:3.20 tar czf /dst/dataprotection-keys.tgz -C /src .

# 4) 容器日志（排障用）
sudo docker compose logs --no-color > "$DEST/compose.log" 2>&1
sudo docker compose ps > "$DEST/compose-ps.txt" 2>&1

# 5) 当前 .env + 登录修复（不含大模型）
cp -a .env "$DEST/env.copy" 2>/dev/null || true
cp -a docker-compose.yml "$DEST/" 2>/dev/null || true
cp -a docker-compose.auth-fix.yml "$DEST/" 2>/dev/null || true

cat > "$DEST/NEXT-RENT.txt" <<'EOF'
本轮运行目录: /opt/agent1/容器化部署/gpu
瘦包目标: /home/featurize/work/agent1/  → 新租 rsync 到 /opt/agent1/ 后 cd /opt/agent1/gpu
登录: admin / 7758521（auditor、viewer 同密码）
AUTH_ACCOUNTS_JSON 必须是带 "Username" 的 JSON；compose up 加 -f docker-compose.auth-fix.yml
embed 要 GPU（libcuda.so.1）；vision 不要 --cache-ram
禁止: docker compose down -v；禁止 rebuild-llama；禁止再传 27G zip（work 里已有瘦包）
EOF

ls -lh "$DEST"
```

本机再拉一份（端口换成**当时**实例 SSH 端口）：

```powershell
scp -P <端口> -r featurize@workspace.featurize.cn:/home/featurize/work/agent1-backup "./featurize-backup"
```

`~/work/agent1-backup` 在退还后仍在云盘；本机再拷一份防云盘误删。

新租恢复库（容器起来且是空库之后）：


### 2.3.1 若 embed 127 / vision 1（b5512 已知坑）

同一枚 CUDA `llama-server`：**embed 不挂 GPU** 会缺 `libcuda.so.1` → **exit 127**；vision 若带 **`--cache-ram`**（b5512 没有）→ **exit 1**。主 LLM 已 healthy 时不要重 load 镜像。

```bash
cd /opt/agent1/容器化部署/gpu
sudo docker compose logs --tail 40 llama-embed llama-vision

sudo python3 - <<'PY'
from pathlib import Path
p = Path("docker-compose.yml")
t = p.read_text()
t = t.replace('      - "--cache-ram"\n      - "0"\n', "")
old = """    networks:
      - agent1_net

  llama-vision:"""
new = """    networks:
      - agent1_net
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]

  llama-vision:"""
if "llama-embed:" in t and old in t and "capabilities: [gpu]" not in t.split("llama-vision:")[0].split("llama-embed:")[-1]:
    t = t.replace(old, new, 1)
p.write_text(t)
print("patched", p)
PY

sudo docker compose up -d --force-recreate llama-embed llama-vision
# VL 上卡要 1–3 分钟；embed 几十秒
sleep 20
sudo docker compose ps
curl -sf http://127.0.0.1:8081/health && echo EMBED_OK
curl -sf http://127.0.0.1:8083/health && echo VISION_OK
curl -sf http://127.0.0.1:5000/health/live && echo API_OK
```

若 vision 日志出现 CUDA OOM：先不要关 OCR，把 vision 的 `-c`/`-np` 改成 `8192` / `1` 再 recreate。若日志是 `invalid argument: --mmproj`，才是旧二进制，需要换 llama tar。

若日志是 `unknown model architecture: 'qwen25vl'`：**不要升 llama tag、不要 rebuild。** 包内这份 VL GGUF 是 `qwen25vl`（常见于 Ollama 转换），b5512 只认 `qwen2vl`。先停掉重启环，文本栈可继续验收：

```bash
cd /opt/agent1/容器化部署/gpu
sudo docker compose stop llama-vision
sudo docker compose rm -f llama-vision
```

OCR 要通：换成 ggml-org 的 `Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf`（约 4.7G，arch=`qwen2vl`）+ 配套 `mmproj-*-f16.gguf`，文件名仍用 compose 里那两个，再 `up -d --force-recreate llama-vision`。不要只换其中一个。

### 2.3.2 登录 HTTP 500（health/live 仍 200）

`/health/live` 不构造 `AuthController`。生产环境 `AUTH_ACCOUNTS_JSON` 为空、`[]`、或被 bash/YAML 吃掉之后，第一次 `POST /api/Auth/login` 会变成 **500** `系统内部错误`（不是 401 密码错）。公司电脑五层编排 L2/L3 都会挂；**不要等 Playwright 跑完**。

另开一个 SSH（隧道那个 `-N` 窗口不要关）：

```bash
cd /opt/agent1/容器化部署/gpu
sudo docker compose exec -T api printenv AUTH_ACCOUNTS_JSON
sudo docker compose logs api --since 2h | grep -E '未处理异常|AUTH_ACCOUNTS|生产环境必须|已加载'
```

4090 已确认的坏值（compose 把 JSON 引号剥掉了）：

```text
[{Username:admin,Password:7758521,Role:admin},{Username:auditor,Password:7758521,Role:auditor}]
```

日志：`Expected a '"' ... BytePositionInLine: 2` → 回退失败 → Production 抛 `必须通过 AUTH_ACCOUNTS_JSON`。  
**不要**把上面这段残值再加引号写回去。整段换成带 `"Username"` 的 JSON，并让 compose **单引号包住整行**（否则 recreate 还会剥引号）。

```bash
cd /opt/agent1/容器化部署/gpu
sudo python3 - <<'PY'
from pathlib import Path

good = (
    '[{"Username":"admin","Password":"7758521","Role":"admin"},'
    '{"Username":"auditor","Password":"7758521","Role":"auditor"},'
    '{"Username":"viewer","Password":"7758521","Role":"viewer"}]'
)

env = Path('.env')
lines, found = [], False
for line in env.read_text(encoding='utf-8').splitlines(True):
    raw = line.lstrip('\ufeff')
    if raw.startswith('AUTH_ACCOUNTS_JSON='):
        lines.append("AUTH_ACCOUNTS_JSON='%s'\n" % good)
        found = True
    else:
        lines.append(line)
if not found:
    lines.append("\nAUTH_ACCOUNTS_JSON='%s'\n" % good)
env.write_text(''.join(lines), encoding='utf-8')
print('patched .env')

yml = Path('docker-compose.yml')
t = yml.read_text(encoding='utf-8')
old = '- AUTH_ACCOUNTS_JSON=${AUTH_ACCOUNTS_JSON:-[]}'
new = "- 'AUTH_ACCOUNTS_JSON=${AUTH_ACCOUNTS_JSON:-[]}'"
if new not in t and old in t:
    yml.write_text(t.replace(old, new, 1), encoding='utf-8')
    print('quoted compose AUTH line')
elif new in t:
    print('compose AUTH line already quoted')
else:
    print('WARN: AUTH line not found; using override file')

Path('docker-compose.auth-fix.yml').write_text(
    "services:\n  api:\n    environment:\n      AUTH_ACCOUNTS_JSON: '%s'\n" % good,
    encoding='utf-8',
)
print('wrote docker-compose.auth-fix.yml')
PY
sudo docker compose -f docker-compose.yml -f docker-compose.auth-fix.yml \
  up -d --force-recreate --no-deps api
# Kestrel 还要加载图谱/库，8s 往往不够；printenv 成功不等于 :5000 已听
for i in $(seq 1 30); do
  if curl -sf http://127.0.0.1:5000/health/live >/dev/null; then
    echo "API_LIVE_OK"
    break
  fi
  echo "wait health/live $i/30"
  sleep 3
done
sudo docker compose exec -T api printenv AUTH_ACCOUNTS_JSON
curl -sS -X POST http://127.0.0.1:5000/api/Auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"7758521"}'
```

期望：`printenv` 里能看到 **`"Username"`**（有双引号），不能再是 `Username:admin`；`curl` 返回 `token`（HTTP 200）。然后再跑公司电脑 `gpu-quick`。以后在这个目录 `docker compose up` 都要带上 `-f docker-compose.auth-fix.yml`，或确认主 compose 那行已加单引号。

## 5. 误用平台默认镜像开机（dpkg 坏了）

这张盘出厂 `/var/lib/dpkg/status` 可能是 0 行。不要跑 `get.docker.com`。

```bash
sudo ls -l /var/lib/dpkg/status /var/lib/dpkg/status-old
# status 0 行、status-old 有上万行：
sudo cp -a /var/lib/dpkg/status-old /var/lib/dpkg/status
sudo sed -i 's|http://archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g' /etc/apt/sources.list
sudo sed -i 's|http://security.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g' /etc/apt/sources.list
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2 unzip
sudo usermod -aG docker "$USER"
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl enable --now docker
sudo nvidia-smi
sudo nvidia-container-cli info | head -20
```

`apt-get install docker.io` 若要新装 `libc6`/`dpkg`/`apt`，立刻停，status 还是坏的。
