# GPU 容器化怎么修（L11 优先，镜像钉 b5512）

> 针对 2026-09-05/06 RTX 3070 日志，以及后续 **RTX 4090（约 25GB 显存）生产包**。不先改业务编排。  
> 现象与分层：[3070 实测记录](../2026-09-06_RTX3070容器实测记录.md)。

**原则：** 改 compose / 镜像能消失的，不要去改页面。不要删 `--jinja` 去「修」D03（在旧二进制上反而会变成 `tools param requires --jinja`）。不要用加大 `--batch-size` 冒充修了 D02（那是逻辑批次，报错要的是 `-ub` 物理批次）。

**尚未在任何有卡机上用 b5512 冒烟。** 不要写成「GPU 全量通过」「`--mmproj` 已实测修好」或「D03 已灭」。

## 工作区已落下（配置 + 工程代码，不是 4090 实测）

- GPU / CPU compose 的 embed 已加 `-ub 2048`（D02）
- 主 compose postgres 已挂 `002` / `004` / `005` / `006`（D04 / D07）
- `compliance.ts` 包装路径已改成斜杠（D12，L4，不扩）
- L11：`llama-vision` 在 `profiles: [vision]`；`ENABLE_VISION_OCR` 默认 **false**；docker-up skip 时 `stop` + `rm -f`
- `Dockerfile.llama*` **构建目标钉 b5512**（D01 `--mmproj`；含 b5478 之后的 streaming 崩溃修复）

生产入口：**4090 只跑离线包 `容器化部署/gpu`**（`load-images` + `docker-up`）。飞致云按量（无关机、只有退还）每次怎么做、退还前拷库和日志：见 [Featurize 4090 按量实例操作手册](./2026-09-07_Featurize4090按量实例操作手册.md)。

## 第一刀 — 4090 生产机：load 离线包 + 冒烟

维护者机已用当前工作区 `Dockerfile.llama` 编 **b5512** 并 `docker save` 进 `容器化部署/gpu/images/`。生产机**不允许跑源码**。

4090 约 25GB ≥ 20GB：docker-up 会设 `ENABLE_VISION_OCR=true` 并**点名**起 `llama-vision`。**六容器是这条生产线的正常形态。** `.env` 不要写 `ENABLE_VISION_OCR=false`。

8GB 卡（3070）仍走同一脚本：显存不足则 skip vision，五容器算正常。

| 修什么 | 怎么做 | 对应 |
|--------|--------|------|
| 缺 `.so` / exit 127 | 包内 llama tar 为 b5512（维护者机 2026-09-07 编，静态 `llama-server`） | 第一波 |
| vision 拒 `--mmproj` | 同一枚 tar；docker-up 点名 `llama-vision` | D01 → D05 |
| tools+stream | 同一枚 tar + API 非流式双保险 | D03 |
| 4090 生产 | 整夹 `容器化部署` → `gpu/` 里 load + docker-up | 六容器 + 8083 |

在 **4090** 上（`容器化部署/gpu/`）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/load-images.ps1
powershell -ExecutionPolicy Bypass -File scripts/docker-up.ps1
# 期望：VRAM ~25GB -> ENABLE_VISION_OCR=true，六容器含 llama-vision

curl http://localhost:8080/health
curl http://localhost:8081/health
curl http://localhost:8083/health
```

日志不得有：`invalid argument: --mmproj`。  
`Cannot use tools with stream`：b5512 理想情况也不该再出现；即使 llama 仍拒，业务侧已改非流式，合规问答应能出结果。  
问一句**非 benzene** 的合规（工具调用应能走）。

生产机不要再 `docker save` / `rebuild-llama`。维护者机若需换 tar，用源码仓 `Dockerfile.llama` 编完再覆盖 `容器化部署/gpu/images/agent1-llama-cuda.tar`。

`docker-compose.release.yml.example` **先不要 pull**。4090 冒烟通过后再谈 `:0.1.0` push。

## 第二刀 — 已有库不要指望「再 up 一次」

`docker-entrypoint-initdb.d` **只在空数据卷首次启动时执行**。已有 `postgres_data` 的，挂了 002 也不会自动灌图谱。

空库（可丢数据）：

```powershell
docker compose down -v
powershell -ExecutionPolicy Bypass -File scripts/docker-up.ps1
```

要保留已有 knowledge 文档时，**不要** `-v`，进库手动跑：

```text
psql → 依次执行
  db/migrations/002_chemical_knowledge_graph.sql
  db/migrations/004_drift_anchor_baseline.sql
  db/migrations/005_drift_probe_tables.sql
  db/migrations/006_drift_probe_templates.sql
```

然后重启 api，日志应出现非 0 物质，且不再报 `drift_anchors` 不存在。

embed 改 `-ub` 后：

```powershell
docker compose up -d --force-recreate llama-embed
```

长文本不应再刷 `increase the physical batch size`。

## 第三刀 — 工作区已改、4090 全量测前不必再补的工程项

| 项 | 工作区 |
|----|--------|
| D06 裸 INSERT | `InsertDocumentAsync` 改为 `ON CONFLICT (source_path) DO UPDATE`，并清旧分块 |
| D08 content_hash | 入库写 SHA-256；增量优先比哈希（mtime 不变也能检出改内容） |
| D11 DataProtection | 卷 `api_dataprotection` → `/app/dataprotection-keys` |
| D13 Seq | 仅当设置 `SEQ_URL` 才连接，不再默认 `localhost:5341` |
| D14 HTTPS 跳转 | 仅 `ASPNETCORE_URLS` 含 `https://` 或 `ENABLE_HTTPS_REDIRECT=true` 才 `UseHttpsRedirection` / HSTS |
| D17 Sanitizer 日志 | 删掉 ≥ 8 字符才 Warning；白名单逻辑未放宽 |
| D03 L7 双保险 | 带 Function Calling 的请求改非流式；HyDE 等 `None()` 仍流式。b5512 若仍拒 tools+stream，业务侧也不再挡一轮 |

仍不要动：

| 项 | 原因 |
|----|------|
| D09 / D15 / D18 | 人点的 / 密码 / 产品缺口 |
| D16 Nginx 499 | 单次客户端断开，`proxy_read_timeout` 已 120s；不当缺陷修 |
| 文件夹 2 未测演示代码 | 不要和这次 GPU 修混推进 master |
| 对外宣称「4090 / `--mmproj` 已实测通过」 | 本包 llama 是 b5512 **构建**产物，尚未在 4090 冒烟 |
