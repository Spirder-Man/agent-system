# Agent1.Api 说明书

ASP.NET Core 8 的薄 HTTP 壳：鉴权、限流、把请求交给 `Agent1` 核心库。不在这里实现禁配算法或检索。

## 边界

| 负责 | 不负责 |
|------|--------|
| 16 个 Controller 的 REST 表面 | 规则引擎、RAG、图谱匹配（[`Agent1`](../Agent1/说明书.md)） |
| JWT 登录 / 刷新 / 注销、角色策略 | 页面路由与按钮显隐（[`agent1-web`](../agent1-web/说明书.md)） |
| 中间件：异常、RequestId、限流、指标、Token 黑名单 | 迁移 SQL、国标 PDF |
| `/health*`、`/metrics`、部分 `/memory*` `/cache/stats` | llama.cpp 进程生命周期 |

**依赖**：项目引用 `Agent1`；PostgreSQL；可选 LLM。  
**调用方**：浏览器（经 Nginx 或 Vite 代理）、E2E、`scripts/demo-compatibility.*`。

## 目录地图

```
Agent1.Api/
  Program.cs                 宿主、DI、中间件顺序、健康端点
  Controllers/               16 个 REST 控制器
  Middleware/                异常 / RequestId / 限流 / 指标 / Token 黑名单
  Services/ScanProgressService.cs
```

`Agent1.sln` 只包含 `Agent1` + `Agent1.Api`。

## 启动与开发

本地（已有 PostgreSQL，无 GPU 时 `.env` 设 `LLM_OPTIONAL=true`）：

```bash
dotnet run --project Agent1.Api
curl http://localhost:5000/health/live
```

Docker：

```bash
bash scripts/docker-up.sh gpu    # 或 cpu；Windows 用 scripts/docker-up.ps1
```

默认端口 **5000**（`API_PORT` / `ASPNETCORE_URLS`）。前端开发代理常见 `127.0.0.1:15000`（SSH 隧道）或直接 `:5000`。演示账号见根 README，勿用于生产。

必填环境变量：`JWT_KEY`（≥32 字符）、`DB_PASSWORD`、`AUTH_ACCOUNTS_JSON`。见 [`.env.example`](../../.env.example)。

## 对外契约

策略（`Program.cs`）：`Admin` = admin；`Auditor` = admin+auditor；`Viewer` = 三角色。前端 `types/api.ts` 与此对齐，无代码生成。

### 控制器一览

路由均为 `api/{Controller}`，动词按 ASP.NET 约定大小写（如 `/api/Auth/login`）。

| 控制器 | 主要路由 | 默认策略 |
|--------|----------|----------|
| Auth | `POST login` `refresh`；`POST logout` 需登录 | 登录匿名 |
| Compliance | `GET summary`；`POST check`；`POST hazard/query`；`POST storage/compatibility` | Viewer；check 为 Auditor |
| Inspection | plans / rounds / reports / assets / `scan` / `quick-check` | 读 Viewer，写 Auditor |
| Tickets | `GET`；`PUT {id}/status`；`POST followup` | 读 Viewer，写 Auditor |
| Audit | `logs` `integrity` `export` `repair-chain` `stats` | **Admin** |
| Admin | `GET db/info` `db/validate` | **Admin** |
| Dashboard | overview / assets / scan / findings / history / report | 读 Viewer，scan 为 Auditor |
| KnowledgeBase | search-mode、rag-test、incremental-load | 读 Viewer，增量加载 Auditor |
| KnowledgeGraph | `POST query` | Viewer |
| Emergency | `POST response` | Viewer（写操作另见方法特性） |
| Multimodal | `POST analyze` | Viewer；analyze 为 Auditor |
| Regulatory | `POST audit` | Viewer；audit 为 Auditor |
| Drift | current / trend / anchors / probes / measure | 读 Viewer，探针作答与测量 Admin |
| Diagnostics | `POST tool-calling` | Viewer |
| Alerts | `POST test` | Viewer；test 为 Auditor |
| Eval | `POST run`；`GET/DELETE status/{taskId}` | Viewer；run/delete 为 Auditor |

### 宿主级端点（非 Controller）

| 路径 | 作用 |
|------|------|
| `GET /health/live` | 进程活着，不查依赖 |
| `GET /health/ready` | 数据库就绪 |
| `GET /health` | DB + LLM + 知识库综合（可 degraded） |
| `GET /metrics` | Prometheus 文本 |
| `GET /cache/stats` | 响应缓存 |
| `GET /memory/stats` 等 | 记忆统计 |

### 中间件顺序

`GlobalException` → `RequestId` → `RateLimiting(100/60s)` → `RequestMetrics` → `Authentication` → `TokenBlacklist` → `Authorization` → `MapControllers`。

## 关键流程

### 登录

`POST /api/Auth/login` → JWT + refresh。角色写入 token。前端存在 Pinia；`401` 时 axios 调 `refresh`。

### 储存兼容性验收

`POST /api/Compliance/storage/compatibility`（需登录）。无 GPU 演示用 [`scripts/demo-compatibility.ps1`](../../scripts/demo-compatibility.ps1) / `.sh`：登录后打该接口，应见甲醇×硝酸禁止同库与 GB 15603。判定在核心库，本层只鉴权与序列化。

### 加一个新接口

1. 在 `Controllers/` 加方法，标 `[Authorize(Policy = ...)]`。  
2. 业务进 `Agent1` 服务，不要把规则写进 Controller。  
3. 同步 [`agent1-web/src/types/api.ts`](../../agent1-web/src/types/api.ts) 与 MSW `handlers.ts`。  
4. 单测放 `Agent1.Tests`（已有 `*ControllerTests` 模式）。

## 本模块怎么测

```bash
dotnet test Agent1.Tests --filter "FullyQualifiedName~Controller|FullyQualifiedName~Api"
```
