# 等级保护口径

本仓库 **不是** 已定级、已备案或已测评的网络安全等级保护对象，也 **没有** 等保测评报告或公安备案证明。

## 依据

- 《中华人民共和国网络安全法》第 21 条：网络运营者应当按照网络安全等级保护制度的要求履行安全保护义务。
- GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》
- GB/T 22240-2020《信息安全技术 网络安全等级保护定级指南》

等保测评的对象是 **某单位正在运行的信息系统**（含机房、网络、主机、应用、数据、管理制度与人员），不是开源软件仓库或单一应用组件。定级、专家评审、主管部门核准、公安机关备案、有资质机构测评，须由网络运营者办理。本项目作为开源组件，不能、也不会代替上述流程。

## 本仓已实现（应用层参照）

对照 GB/T 22239 第三级中与 **安全审计、访问控制、身份鉴别** 相关的控制点精神，本仓实现了：

| 实现 | 对照意图 |
|------|----------|
| 操作审计写入 `audit_logs`，默认留存 180 天 | 审计记录留存不少于 6 个月 |
| SHA256 哈希链与完整性校验 | 审计记录防篡改（应用层做法） |
| JWT + admin / auditor / viewer | 身份鉴别与最小权限雏形 |
| 敏感信息脱敏 | 敏感数据保护的一部分 |
| 可私有化部署 | 数据可不出域的部署取向 |

以上 **不等于** 已定级备案，也 **不等于** 已由测评机构出具通过结论。

## 明确未覆盖

管理制度与人员、物理安全、网络边界与入侵防护、集中管控、备份容灾、密码模块与时钟同步、审计管理员与系统管理员的职责分离、生产环境真实客户端 IP 等，均不在本开源仓承诺范围内。缺口示例见 [全量问题台账.md](../数据库化石/全量问题台账.md)（如 `audit_logs.ip_address`）。

园区或企业将本软件纳入生产系统时，须由该网络运营者按法律法规对 **所在信息系统** 自行定级、备案、测评；本软件仅可作为该系统中的应用组件配合整改。
