## 六、事实库（只能用这些）

### 6.1 作品是什么

Agent1 是面向化工园区危化品**合规审查**的开源 AI Agent，不是通用聊天机器人，也不是已经交付的园区生产系统。

目标用户（角色，不要写成已签约客户）：

- EHS / 企业安全员：日常问「两种物质能否同库」「安全距离多少」
- 安全管理部：合规自查、整改工单、巡检
- 核查辅助人员：对照结构化结论做核查准备
- 系统角色：JWT 三角色 `admin` / `auditor` / `viewer`

解决的核心矛盾：通用大模型会编造或补错法规编号（例如补错年份、写出知识库里不存在的 GB 号）。化工场景里，错一条编号的代价不是「回答体验差」，而是误导现场储存与作业。本系统把**法规编号、储存禁忌、安全距离**放在确定性代码通道，大模型只做自然语言解释和建议。

明确不做：

- 不替代持证安全管理人员的法定职责
- 不发布、不随仓库分发国家标准全文
- 不宣称自身为已定级备案的等保对象
- 本仓未对接真实 ERP/WMS/EHS 生产数据

### 6.4 双通道（必须作为【图 2】，这是创新点 1 的技术内容）

主路径（完整 GPU / 有 LLM 时）：

1. `IntentRouter.Route()` 按关键词把化工合规问题分到化学合规执行路径。
2. Semantic Kernel Auto Function Calling 选择工具。工具包括但不限于：`CheckHazardCategory`、`CheckStorageCompatibility`、`GetSafetyDistance`、`GetMajorHazardThreshold`、`LookupChemicalProperties`、`CheckRegulationVersion`。
3. `ApplyDecoupledPipeline()`：
   - Function Calling 设为需要工具时，若 `toolCalls` 为空：视为违约，**丢弃全部 LLM 输出**，改确定性兜底；
   - `ComplianceFactExtractor` 从工具返回值提取结构化事实；
   - `OutputSanitizer` 白名单硬拦截：不在工具返回列表中的法规编号直接删除；
   - `FactAssembler` 用 C# 模板渲染「适用标准」等事实句；
   - `ResponseMerger` 合并事实通道与解释通道。

两通道职责：

| 通道 | 职责 | 实现 | LLM |
|------|------|------|-----|
| 事实通道 | 法规号、禁忌结论、危险类别、安全距离等结构化事实 | 工具 → Extractor → FactAssembler | 不参与编号生成 |
| 解释通道 | 专业解读、操作建议、注意事项 | LLM；输出模板为【专业解读】【操作建议】【注意事项】 | 参与 |

四层拦截（可做成小表，不要再扩）：

1. `PromptSanitizer`：系统提示去掉「请引用法规编号」，改为只要专业解读。
2. `PromptSanitizer` 处理工具结果：剥离法规标签，降低模型照抄/改写编号的机会。
3. `OutputSanitizer`：白名单之外的 GB 号硬删除。
4. FC 违约：无工具调用则丢弃模型输出。

`RegulationRefs` 是法规编号的唯一白名单来源。模型不能发明 GB 编号。

无 GPU 演示：不走 llama.cpp，由 `DeterministicRuleEngine` 等规则引擎根据种子库给出储存禁忌等结论。这不是「演示造假」，而是架构上的降级路径，与「LLM 熔断仍可给可审计结论」是同一设计。

检索（创新点 3，一段话即可）：中文化工短查询使用自研 NGram（完整词 + 2-gram + 单字）+ 内存 BM25，向量检索使用 pgvector，混合权重约 BM25 0.4 / 向量 0.6。采用 NGram 而非通用中文分词器，是为避免把「过氧化氢」一类术语切碎。不要写实验表格数字（除非原文有且你未提供——你未提供评测分数，**禁止编工具调用率、准确率**）。

审计与身份：

- 操作写入 `audit_logs`，默认留存 180 天
- SHA256 哈希链（应用层）
- JWT：admin / auditor / viewer
- 敏感信息脱敏
- 配置开关：`UseDecoupledArchitecture` 默认开启

生产配置（PDF 里只写「必填项名称」，不要写真实值）：`JWT_KEY`（不少于 32 字符）、`DB_PASSWORD`、`AUTH_ACCOUNTS_JSON`，只存在本机 `.env`，不进 Git。
