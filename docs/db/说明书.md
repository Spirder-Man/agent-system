# db 说明书

PostgreSQL 16 + pgvector 的 schema、迁移和危化品结构化种子。国标 PDF 与运行时向量不属于本模块。

## 边界

| 负责 | 不负责 |
|------|--------|
| `init_database.sql` 首次建表与基础种子 | `knowledgebase/` 里的虚构园区文本、国标全文 |
| `db/migrations/*.sql` 增量 | embedding 写入（运行时，核心库 + `:8081`） |
| compose 挂载的 init 顺序 | 业务判定（[`Agent1`](../Agent1/说明书.md)） |
| 校验脚本 `verify_*.sql` | 备份/容灾、等保测评对象 |

评委无 GPU 的甲醇×硝酸验收**只依赖本模块第 1 层种子**，不依赖向量、不依赖国标文件。口径见 [../../knowledgebase/README.md](../../knowledgebase/README.md)。

## 目录地图

```
init_database.sql              仓库根：compose 挂为 01_init.sql
db/
  init_database.sql            与根文件对照用（以 compose 挂载的根文件为准）
  migrations/
    002_chemical_knowledge_graph.sql
    003_cleanup_stale_chemical_aliases.sql
    004_drift_anchor_baseline.sql
    005_drift_probe_tables.sql
    006_drift_probe_templates.sql
    007_unify_incompatible_categories.sql
    008_restore_ltm_active.sql
  chemical_substances_v2.sql
  cleanup.sql
  verify_database.sql
  verify_simple.sql
```

`docker-compose.yml` 把根 `init_database.sql` 与 **002 / 004 / 005 / 006** 挂进 `docker-entrypoint-initdb.d/`。仅**空数据卷首次**执行。已有 `postgres_data` 时要 `docker compose down -v` 或手工 `psql`。003/007/008 需按运维流程补跑，不要假设 compose 已挂全部编号。

## 启动与开发

```bash
# 随栈
bash scripts/docker-up.sh gpu   # 或 demo compose 只起 Postgres + API

# 校验（容器内或本机 psql）
psql -U postgres -d chemical_park_ai_agent -f db/verify_simple.sql
```

库名默认 `chemical_park_ai_agent`（`DB_NAME`）。口令只写 `.env`。

## 对外契约

- 种子物质、禁忌、安全距离、法规号白名单：SQL，不是 PDF。  
- 审计表结构与哈希链字段以当前迁移 + [`数据库化石/精读-audit_logs_三层考古.md`](数据库化石/精读数据表设计/精读-audit_logs_三层考古.md) 对照代码。  
- 漂移探针模板：006。

表级考古（字段来源、谁写谁读）在 [数据库化石/](数据库化石/)；速查 [数据库化石/数据库速查手册.md](数据库化石/数据库速查手册.md)。问题台账是历史核销，不是运行时 API。

## 关键流程

1. **空库拉起**：Postgres 健康 → initdb 跑 01+02+04+05+06 → API 连上即可做储存兼容性。  
2. **加迁移**：新文件编号递增；若需首次安装自动跑，还要改 compose `volumes`；已有卷写明手工升级步骤。  
3. **丢数据**：先看 [数据库化石/2026-08-11数据丢失疑案闭环报告.md](数据库化石/2026-08-11数据丢失疑案闭环报告.md)，不要直接 `down -v` 当常规手段。
