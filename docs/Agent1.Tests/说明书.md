# Agent1.Tests 说明书

xUnit 测 `Agent1` 与 `Agent1.Api` 的逻辑与部分 HTTP。前端 Vitest、Playwright、GPU 五层脚本不在这里。

## 边界

| 负责 | 不负责 |
|------|--------|
| 核心库纯逻辑（规则引擎、RAG 组件、哈希链、漂移…） | `agent1-web` 的 Vitest |
| 标了 `Category=Integration` 的 DB/API 集成 | Playwright（[e2e](../e2e/说明书.md)） |
| 与 Controller 的契约冒烟 | `scripts/gpu-five-layer.ps1` |
| 旁路：`ArchitectureTest/` 分层规则、`Benchmark/` 性能 | 改生产代码路径 |

分层总入口：[../platform/测试总纲.md](../platform/测试总纲.md)。数字以总纲与最近 CI 为准，本文不重复刷条数。

## 启动与开发

```bash
# CI 同款：跳过要数据库的集成
dotnet test Agent1.Tests --filter "Category!=Integration"

# 全量（本机 PostgreSQL 已起、连接串与 .env 一致）
dotnet test Agent1.Tests
```

覆盖率脚本：[`scripts/check-coverage.ps1`](../../scripts/check-coverage.ps1)。CI 期望见 `.github/workflows/ci.yml`（约 60% 行覆盖门禁，以工作流为准）。

## 对外契约

- 集成测试通过环境连接真实库，失败常见原因是未起 Postgres 或种子未灌。  
- 测 API 用 `CustomApiWebApplicationFactory`，不要在测试里 new 生产 `WebApplication` 而不替换 LLM。  
- Stub 在 `Stubs/`：`StubLlmService`、`StubDatabaseService` 等。

## 关键流程

1. **纯逻辑**：规则引擎、GB 规范化、分块、哈希链 — 无 IO。  
2. **集成**：`Category=Integration`，依赖 `chemical_park_ai_agent`。  
3. **架构收敛**：`ArchitectureTest` 或本项目内 `ArchitectureConvergenceTests`，防错误项目引用。

## 本模块怎么测

就是上面的 `dotnet test`。GPU 结论准确率、llama 健康走 [../infra/说明书.md](../infra/说明书.md) 的五层两档，不要用本项目的 Skip 集成去宣称 gpu-full 通过。
